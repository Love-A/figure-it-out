Good to know

          
    
            
  • Install the kiosk app before the profile reaches the device – Assigned Access starts it at sign-in, so it has to be there.
    • 
            
  • A device holds one Assigned Access configuration. Assign only one such profile per device – two profiles setting the same OMA-URI overwrite or conflict with each other.
    • 
            
  • A kiosk (single-app) profile can only be assigned to user accounts, not to user groups. Don't assign administrator accounts.
    • 
            
  • Automatic sign-in doesn't work if the PreferredAadTenantDomainName policy is set or Exchange ActiveSync password restrictions are active.
    • 
            
  • Avoid accounts targeted by Conditional Access that requires MFA or terms of use – the sign-in would need interaction.
    • 
            
  • Local accounts aren't shown on the sign-in screen of Entra-joined devices. If needed, enable WindowsLogon/EnumerateLocalUsersOnDomainJoinedComputers.
    • 
            
  • Alt+F4, Alt+Tab and Ctrl+Alt+Del aren't blocked in a restricted user experience. Use Keyboard Filter if you need to.
    • 
            
  • A Store app update can change the app's AUMID – the configuration then has to be updated.
    • 
            
  • Intune's kiosk template sets up multi-app kiosks on Windows 10 only. On Windows 11, use a custom profile with this XML.
    •

Import

  

    
Paste, or drop a file. The generator recognizes Assigned Access XML, an Intune custom profile as Graph JSON (omaSettings) and Intune's kiosk template (windowsKioskConfiguration, e.g. exported from Microsoft Graph). HTML-encoded XML (&lt;…) works too.

Add common apps

  

    
Built-in Windows apps with known AUMIDs and paths. If in doubt, check on a reference device with Get-StartApps.

    

  

  





  
Get apps from a reference device

  

    
1. Run this in PowerShell on a device where the apps are installed. The result lands on the clipboard: Store apps with their AUMID, desktop apps with their path and Start shortcut.

    


$sh = New-Object -ComObject WScript.Shell
$store = Get-StartApps | Where-Object AppID -like '*!*' |
    ForEach-Object { [pscustomobject]@{ Name = $_.Name; AUMID = $_.AppID } }
$desktop = "$env:ProgramData\Microsoft\Windows\Start Menu\Programs",
           "$env:APPDATA\Microsoft\Windows\Start Menu\Programs" |
    Get-ChildItem -Recurse -Filter *.lnk -ErrorAction SilentlyContinue | ForEach-Object {
        $target = $sh.CreateShortcut($_.FullName).TargetPath
        if ($target -like '*.exe') { [pscustomobject]@{ Name = $_.BaseName; Path = $target; Link = $_.FullName } }
    }
@($store) + @($desktop) | ConvertTo-Json | Set-Clipboard

      
    

    
2. Paste the result here. Plain Get-StartApps output works too, but only gives paths for apps in known folders and no shortcuts.

    
    

    

      
      
    

    

    
Shortcuts under %APPDATA% are per user – the kiosk account only has them if Windows or your packaging creates them for it. Prefer shortcuts under %ALLUSERSPROFILE%.
